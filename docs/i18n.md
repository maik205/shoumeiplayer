# Internationalization

Android string resources are the source of truth for application-owned text. English resources live under `app/src/main/res/values/`, and supported locale tags are declared in `app/src/main/res/xml/locales_config.xml`.

## Resolve text in Compose

Use `stringResource(R.string.some_key)` for text that does not leave the composition. Use Android formatting arguments and plurals instead of joining translated fragments.

ViewModels and repositories must not resolve resources into English strings. Use `UiText.Resource` when application-owned text crosses into Compose. Reserve `UiText.Dynamic` for text returned by Jellyfin or another external source, then call `resolve()` at the Compose boundary.

## Name resources

Prefix keys by feature, such as `tv_`, `settings_`, or `player_`. Name the meaning instead of copying the current English wording.

Mark protocol tokens, URLs, and other fixed values with `translatable="false"`.

## Add a locale

1. Add translated resources under a qualified directory such as `app/src/main/res/values-de/`.
2. Translate complete messages without concatenating fragments.
3. Add the BCP 47 locale tag to `app/src/main/res/xml/locales_config.xml`.
4. Check truncation, focus behavior, long text, and right-to-left layout on a television target.

Android exposes declared locales in the per-application language settings on supported versions.
